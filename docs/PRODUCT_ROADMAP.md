# Neo Agent 产品深化路线图

## 目标产品

面向多个聊天群、多个可配置虚拟群友的 Agentic 平台。角色不是“一个聊天 prompt”，而是可以独立装配模型策略、性格/关系、记忆域、工具权限、事件订阅和部署通道的原子 Agent；全局控制面负责编排、观察、授权与生命周期管理。

## 现状模块盘点

| 领域 | 旧项目已有能力 | 新架构的归属/下一步 |
|---|---|---|
| 对话 | `chat_agent`、连续对话与提示词组装 | Agent Runtime 插件；拆分计划/执行/总结，不让 TUI 直接调用业务逻辑 |
| 人格 | 角色设定分散在对话和 GUI 配置 | `characters/<id>/manifest.json` + 独立 personality 插件 |
| 记忆 | 短期/长期记忆、知识库、基础知识 | PyVDisk FS 放结构化事实，VectorDisk 做语义召回，LogDisk 保存事件轨迹 |
| 关系/情绪 | 情感分析、印象和累计评分 | 每个 Agent×用户的关系状态机与可解释变更事件 |
| 工具 | NPS 动态扫描与关键词/LLM判断 | 签名化能力清单、权限声明、PyVDisk AgentSandbox 审计适配器；以 LangChain tool 接入 |
| 群组事件 | event manager、通知/任务事件 | Event Bus + 订阅路由 + 幂等处理器 |
| 日程 | 计划生成、相似度检查、日程管理 | 日程 Agent 插件，接入定时触发、冲突仲裁及确认工作流 |
| 管理面 | 多个 Tk 窗口（设置、数据库、日程、调试等） | 一个全局 TUI：总览、Agent、插件、会话、记忆、事件、部署、运行审计 |
| 持久化 | SQLite 统一数据库 | 全部替换为 PyVDisk DataDisk API：FS/Vector/Log/Checkpoint/WAL |

## 产品功能深化路线

### A. 原子 Agent 与角色市场
1. 定义 `AgentManifest`：角色身份、提示模板、模型配置引用、工具能力、记忆域、事件订阅、版本和依赖。
2. 生命周期：草稿 → 校验 → 启用 → 暂停 → 归档；每个角色可以独立启停和回滚到上个 manifest 版本。
3. 插件协议分为 `人格`、`模型供应商`、`记忆策略`、`工具`、`群平台适配器` 五类，按能力声明装配而非在主进程散落条件分支。

### B. 群聊社交智能
1. 多角色在同一群的发言仲裁：触发概率、冷却时间、话题相关性、群活跃度与角色间互斥/接力规则。
2. 用户与 Agent 的关系档案：熟悉度、信任、共同经历与边界；每次变化有来源和解释，不直接把情绪分数当黑盒状态。
3. 社会图谱记忆：人物、群、事件、承诺和实体关系，支持“谁在什么群说过/约定过什么”的可追溯检索。
4. 群氛围和话题状态摘要：按窗口增量更新，闲聊、求助、冲突、通知、计划等场景选择不同策略。

### C. 事件驱动的 Agentic 工作流
1. 把“收到消息、被提及、定时、关系变化、任务完成”统一成带 event_id 的事件信封。
2. Workflow 插件提供触发器、条件、动作、审批点；通过 PyVDisk 队列/检查点持久化运行状态，支持恢复与幂等重放。
3. 为外部副作用（发消息、创建日程）实施 outbox 与人工确认策略；明确 PyVDisk 单镜像事务无法覆盖外部平台事务。

### D. 运营与可观测性
1. TUI 添加实时会话流、Agent 状态矩阵、插件依赖图、事件队列、记忆检索解释和存储容量视图。
2. 一键创建/复制角色、Dry-run、回放会话、权限审查、运行中暂停与安全终止。
3. 运行指标：响应延迟、模型 token/cost、工具调用成功率、主动发言率、记忆命中率；所有看板从 LogDisk/Audit 读模型生成。

### E. 建议交付阶段
- **阶段 1（完成）**：Dev 分支、Textual 全局控制台、PyVDisk 唯一存储适配器、角色档案 CRUD（归档代替物理删除）、可信插件注册/启停、LangChain 有界工具调用和 transcript；旧 Tk/SQLite 启动与运行路径已完全移除。
- **阶段 2（旧功能迁移完成）**：领域服务、TUI 管理流及 PyVDisk DataDisk 集成测试均已落地。当前已有 LogDisk 事件流、DurableQueue 到期提醒 worker、重试/失败可观测性、周周期推进、日程冲突与时间分析、记忆/知识/关系/环境 CRUD；已新增日程自然语言规划/相似项审阅、持久化人机提问，以及 LangChain 多角色任务型协作与断点续跑；协作 workflow 已同步投影到事件管理流；NPS 参数 schema 现在在测试和调用入口验证，测试执行不写入/篡改已安装插件；关系页已具备情绪维度字符仪表与长期摘要时间线。控制台全 17 页快捷键/刷新有 Pilot 覆盖；日程临时建议的预览/采纳/显式创建及相似日程复核门禁有 Pilot 覆盖；新版配置包支持按类别选择导入/导出、密钥过滤、预览、整包预校验与导入审计，服务和 TUI 选择流均有测试。迁移矩阵已用于逐项核对，替代测试通过；旧源码、旧测试、旧示例、旧 GUI 校验脚本及旧格式配置样例已删除。
- **阶段 3**：上下文编排、VectorDisk 记忆召回、知识来源/置信度生命周期及可回放会话轨迹。
- **阶段 4**：多群平台 adapter、主动发言仲裁、经审批的日程/提醒外部副作用闭环。
- **阶段 5**：TUI 实时运行观测、离线模拟回放、记忆/关系审核、权限审批、诊断与部署管理。

## 当前架构约束

- 不迁移、不读取旧 SQLite 数据；不保留旧 schema 兼容。
- 新代码只能依赖 `DiskStore`/PyVDisk 的公开边界，不直接碰镜像文件结构。
- 插件工具默认最小权限、可审计；网络/API 工具需单独声明能力和外部副作用补偿策略。
- LangChain 是编排/工具协议层，不是持久化层；存储能力统一由 PyVDisk 提供。

## MaiBot 对标后的产品深化建议

MaiBot 的产品目标不是简单地增加聊天接口，而是营造“像群友一样”的交互：自然表达、判断何时发言/沉默、多人风格适配、持续理解新词与关系，并以插件和事件系统扩展。其当前源码布局也清楚地区分了消息接入/回复、心流与主动交互、学习器、人物信息、记忆、平台驱动、插件运行时和运营管理。Neo Agent 不复制其实现或旧式单体数据层，而是把这些能力映射到 LangChain 的组件边界和 PyVDisk 的 FS/Vector/Log/Checkpoint/Queue。

**当前已迁移的产品基线**：Textual 全局控制面；角色档案与单角色对话；PyVDisk AgentSandbox/LangChain 工具；新格式 NPS；LogDisk 事件与 DataDisk 领域文档；持久化日程 worker、重试/失败审计、周周期推进、冲突检查、时间区间/空闲时段/统计；会话及记忆管理与批量清理确认。尚无真实群平台连接器、多角色发言仲裁、自动记忆学习及完整镜像快照 API。旧 Tk/SQLite/NPS 运行模块与旧测试、示例、GUI 校验脚本已从仓库移除。群平台连接器、多角色发言仲裁、自动记忆学习、完整镜像快照 API 与外部通知交付仍是后续产品深化项，不是旧格式兼容范围。

**建议按产品能力纵向交付，而非只做基础设施**：

1. **群聊感知与发言仲裁**：建立 `IncomingMessage`/`ReplyCandidate` 事件模型，聚合群聊窗口与话题状态；每个角色按相关性、冷却、群活跃度、置信度和静默边界产生候选，再由可解释仲裁器决定回复、延迟或沉默。先做离线回放和 TUI 调参，再接平台。
2. **可成长的人格和关系**：新增关系状态机（熟悉度、信任、互动边界、共同经历），每次更新都需引用来源事件和解释；角色可按频道建立不同熟悉度，而不是全局一个情绪分数。
3. **记忆/圈内语言学习**：短期窗口摘要 → 可验证长期事实 → VectorDisk 召回；为事实记录来源、置信度、有效期与用户纠正状态。新词/黑话先进入待确认候选，通过 TUI 审核后再用于表达，防止未经核实的群聊内容固化为“事实”。
4. **插件和平台扩展**：定义版本化 `AgentManifest`、能力权限、事件订阅、健康状态与隔离执行契约；先实现一个平台 adapter 和一个端到端消息事件插件，再开放第三方包安装/签名，不从数据盘动态执行任意 Python。
5. **日程到闭环工作流**：目前已有到期 worker、重试/失败审计与“待发送 workflow”状态，尚无真实通知 adapter 与完整 outbox 交付闭环。下一步接入平台 adapter，并完成幂等外部发送与回执追踪。
6. **多模态群友表达**：在纯文本群聊闭环稳定后，以声明式工具能力接入图片理解、表情/语音等；可独立禁用、记录推理来源和预算，不让视觉能力绕开工具权限。

### 近期可验证的产品切片

- **切片 A：离线群聊模拟器**：导入新格式的回放事件（不兼容旧 SQLite），运行多个角色和仲裁策略，在 TUI 时间线比较回复/沉默及原因。
- **切片 B：关系与记忆工作台**：按群/用户查看证据链、修订/遗忘、置信度变化和 VectorDisk 命中解释。
- **切片 C：真实群聊最小闭环**：单平台 adapter → 幂等事件队列 → 单 Agent 候选回复 → 安全策略 → 人工确认/发送 → LogDisk 回执。

排序建议：先 A（无平台副作用，可快速验证“像群友”核心）→ B（建立长期个性化）→ C（接入真实环境）。在这些产品切片完成前，不应把新 TUI/新持久化骨架描述为旧功能迁移完成或 MaiBot 等价。
